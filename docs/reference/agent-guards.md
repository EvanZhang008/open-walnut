# Machine guards for agent sessions

Hooks and server checks that keep an agent session from killing other sessions, putting content on a command line, making sound, or taking the person's keyboard and mouse.

_Moved from the root `AGENTS.md` on 2026-11-11; the root file keeps a one-line summary of each rule._

## NEVER force-kill Claude Code processes

- **NEVER force-kill Claude Code processes**: bypasses on-stop hook

## A CLI's command line carries paths, never content; nobody kills by pattern

- **A CLI's command line carries paths, never content; nobody kills by pattern** (2026-10-31: `pkill -f "clone.*playwright"` matched the inline `--settings` hook text of every CLI and SIGTERMed every session on the Mac, then an unquoted heredoc ran the same pkill in backticks). Every claude spawn (both daemon twins' session start, every one-shot, the in-process fallback) runs its argv through `src/providers/cli-argv-files-core.ts`: `--settings`, `--mcp-config`, `--append-system-prompt`, `--system-prompt` become content-addressed files in `<streams>/argv` (0600); the server and the daemon's registry keep the inline form. A PreToolUse Bash hook (`src/providers/pattern-kill-guard-hook.ts`, off: `WALNUT_PATTERN_KILL_GUARD=0`) refuses `pkill`, `killall` and `pgrep` with `kill` wherever the shell would run them. A second one (`src/providers/codex-provider-guard-hook.ts`, off: `WALNUT_CODEX_PROVIDER_GUARD=0`) refuses a Codex model run (`codex exec`, `codex review`, a bare `codex`) that has no `-c model_provider=<name>` after its subcommand. Long hook scripts leave the settings too (2026-11-11: the settings had reached 100 KB, the room of a host spawn template string): when the daemon writes a session's settings file it moves every hook command of 512 characters or more to `<streams>/argv/hooks/<hash>.sh` and runs it with `. '<file>'` in the hook's own shell (a file that is gone refuses a PreToolUse call, exit 2); a spawn template, one string per argv entry, carries them as `@walnut-hook-file:<hash>` tokens with each text beside the settings as `--walnut-hook-file <text>` (`src/providers/hook-files.ts`, capability `hook-files-v1`), kept on the host under its own `spawn-template-hf-*` name, and a start puts the texts back before it records its args (`inlineArgs`), so a registry never holds that form and a daemon from before (a rollback) re-spawns what it knows, never removes a file in `hooks/`, and finds no template it cannot run. Ratchet: `tests/providers/cli-argv-content-ratchet.test.ts`.

## Type checks never pile up

- **Type checks never pile up** (`src/providers/typecheck-guard-hook.ts`, a PreToolUse Bash hook in every Claude Code session; 2026-11-11, the "Memory pressure" alarm: seven `tsc --noEmit` runs of 2 to 3 GB on the Mac, one session holding four copies of one web check, each started again after the Bash tool sent the slow one to the background, with swap at 15.7 of 17.4 GB). A session's new type check (`tsc`, `vue-tsc`, `tsgo`, through node, bun, npx or `bun x`, and a package script named lint, typecheck or type-check) is refused while one it started still runs, and any session's while the machine runs one per 16 GB of memory (at least 2), the refusal naming the runs that hold it; it reads the command with the git hooks' shell splitter (`shell-split-awk.ts`) and the running ones from `ps`, each counted once at its outermost type check, and fails open. Off: `WALNUT_TYPECHECK_GUARD=0`; a host's count: `WALNUT_TYPECHECK_MAX`. Ratchet: `tests/providers/typecheck-guard-hook.test.ts` (every package script that runs tsc is read by its name or listed as a build).

## No agent makes sound on the machine it works on

- **No agent makes sound on the machine it works on** (2026-11-07, at night: a voice test on someone else's Mac unmuted it at 70% with `osascript ... without output muted`, then spoke and played music through its speakers; a rule in the user's profile did not stop it). One rule set (`src/providers/sound-rules.ts`), two twins over one case table (`tests/providers/sound-guard-cases.ts`): a PreToolUse Bash hook in every Claude Code session (`src/providers/sound-guard-hook.ts`, POSIX awk, read wherever the shell would run the command: wrappers, `$(...)`, `bash -c`, heredocs, pipes into a shell, `ssh host cmd`, osascript's AppleScript, an interpreter's inline code) and the same judge in host_exec on the server for every host (`src/providers/sound-guard.ts`, `409 makes_sound`, no override). Refused: `say` without `-o`, espeak without `-w`, afplay and the other players, a media app told to play, and any volume change or unmute (osascript `set volume`, amixer, pactl, pamixer, wpctl: any level, 0 and "with output muted" included); a mute alone, reading the volume, a null output and choosing an output device stay allowed, so voice tests feed a file or a virtual device. A script file it cannot see is not read. The hook's awk program rides as gzip + base64; like every long hook script it reaches the host as a file of its own (`src/providers/hook-files.ts`, below), so each script, not the settings, must stay under 100 KB. The same guard refuses real foreground input on the machine (2026-11-09: a session drove `cliclick` on a Mac while its person watched a video there): `cliclick`, `xdotool`, `ydotool`, `wtype`, `xte`, `dotool`, Peekaboo's click, type, press, hotkey, scroll, swipe, drag, move and paste, System Events clicks and keys from osascript, and input event APIs in an interpreter's code (CGEventPost, pyautogui, pynput, robotjs), each also when a package runner (`npx`, `bunx`, `uvx`, `pipx run`, `uv run`, `pnpm dlx`) or `python -m` starts it (2026-11-11); host_exec answers `409 foreground_input`. A test drives its own window from inside it (Playwright, XCUITest, `xcrun simctl io`), and a command that truly must drive a window it owns this way names why on its own line (`WALNUT_INPUT_REASON='<why, 10+ characters>'`). Case table: `INPUT_CASES` in `tests/providers/sound-guard-cases.ts`. On for everyone; off with `WALNUT_SOUND_GUARD=0` on the server. A test browser or Simulator makes no sound and opens no audio output either (2026-11-08: Playwright WebKit runs on a Mac with a person near it switched its speaker on at every page's first click, through the reminder chime's audio unlock, 278 times one night; a muted output was not enough, the person heard it): under automation (`navigator.webdriver`) the page tries no audio (`src/lib/automation-silence.ts`: no chime, media never plays, play() rejects as an autoplay block does and an autoplay element is paused, an AudioContext is made with no output device where the engine can (Chromium's `sinkId: { type: 'none' }`) and refused anywhere else (WebKit), speech never spoken; `window.__walnutAudio` counts what a page tried; Walnut's Board and rich-island frames run it first), every Playwright context runs that silencer at document start in every frame, a plugin's page and a dev server in the Web view included (`tests/e2e/browser/pw-silence.ts`, imported by every Playwright config), the Macs' WebKit runners load the same rules into every run from the Mac's main whatever branch it builds (`tests/e2e/browser/pw-silence-preload.cjs`, `NODE_OPTIONS=--require`), and so does every Playwright run under a Walnut session: both daemon twins write that preload into the host's state dir and start every session (Claude Code and ACP) with it first in `NODE_OPTIONS` and `BUN_OPTIONS` (`src/providers/pw-silence-core.ts`, generated into the committed copy by `scripts/pw-silence-preload.ts`; it acts on any load of playwright-core, a runner, a worker or a script of the session's own, and under Bun on a main script that names Playwright; `WALNUT_PW_SILENCE=0` on the daemon turns it off; ratchet `tests/providers/pw-silence-twins-e2e.test.ts`), Chromium projects launch with `--mute-audio`, and the iOS app is silent in the Simulator, under XCTest and with `-walnut.silentAudio` (`AudioSilence`, read by every player and every WKWebView configuration, `-walnut.allowSound YES` for a person; every UI test launch passes it). On a Mac no WebKit test browser ever becomes the frontmost app (2026-11-08: two tasks' headless ones took the front from the person 8 times in 8 seconds, and a Cmd+Q meant for another app quit one): the preload starts each through a runner that loads a library making it background-only (`src/providers/pw-noactivate-core.ts`, `WALNUT_PW_ACTIVATE=1` for a person; ratchet `tests/providers/pw-noactivate.test.ts`). Nor does a test open the Simulator app: a running one is an ordinary app another program can bring to the front, launched with `open -g` or not (checked by the system log), so scripts boot devices headless with `xcrun simctl boot` and never run `open … Simulator` or `maestro start-device` (ratchet `tests/scripts/no-simulator-window.test.ts`). No window of the Mac app or its native tests beeps for a key nobody handles (`QuietKeyWindow` in `desktop/main.swift`; 2026-11-08: a native test driver's Escape, Enter and arrow keys into a web view sounded the alert all night), and a Swift file that makes key events says why none beeps (ratchet `tests/desktop/quiet-window.test.ts`). Nothing touches the machine's volume. Ratchet: `tests/web/automation-silence.test.ts` (every sound API, sandboxed frame and iOS sound site listed).
