## Frozen contract (all agents build against this)

### Letter record (store)

```
{
  id: string,                      // 'lt-' + timestamp36 + '-' + rand
  subject: string,
  type: 'completion' | 'action_required' | 'review' | 'info',
  bodyFormat: 'html' | 'markdown',
  textPreview: string,             // <= 300 chars, plain text, for envelope + push
  sender: { sessionId, sessionTitle?, taskId?, taskTitle?, project?, host },   // stamped server-side
  createdAt: number, read: boolean, pinned: boolean, archived: boolean,
  actions?: Array<{ id: string, label: string, description?: string }>,
  answered?: { actionId: string, label: string, freeText?: string, at: number },
  thread: Array<{ from: 'agent' | 'human', text: string, bodyFormat?: 'html'|'markdown', bodyFile?: string, at: number }>
}
```

Storage: `WALNUT_HOME/human-inbox/index.json` (records, no bodies) + `WALNUT_HOME/human-inbox/bodies/<id>.html|.md` (+ `<id>.r<n>.<ext>` for rich thread replies). Body cap 200KB. Cross-process safety via updateJsonFile, same pattern as notifications store.

### Routes (new file src/web/routes/human-inbox-v1.ts, mounted from api-v1.ts, NOT server.ts)

- `POST /api/v1/human-inbox` send: `{subject, type, html?|markdown? (exactly one), text?, actions?, task_refs?, pin?}`; caller sid from `x-walnut-caller-sid` header; returns `{id}`
- `GET /api/v1/human-inbox?archived=1` list envelopes (index records, no body content)
- `GET /api/v1/human-inbox/:id` full letter: record + body content + thread body contents
- `POST /api/v1/human-inbox/:id/reply` agent thread reply `{html?|markdown?, text}`: flips read=false
- `POST /api/v1/human-inbox/:id/read` `{read: boolean}`
- `POST /api/v1/human-inbox/:id/pin` `{pinned: boolean}`
- `POST /api/v1/human-inbox/:id/archive` `{archived: boolean}`
- `POST /api/v1/human-inbox/:id/answer` `{actionId, freeText?}` human clicks an action: records `answered`, appends human thread entry, delivers to origin session
- `POST /api/v1/human-inbox/:id/human-reply` `{text}` human free-text reply: thread + deliver to origin session

### Ops (new src/ops/human-inbox.ts, imported in src/ops/index.ts)

- `human_inbox_send` bind POST /human-inbox; input mirrors route body; tags `{readonly:false, remote:'allow'}`
- `human_inbox_reply` bind POST /human-inbox/:letter/reply with `letter` path arg; same tags

### Event (src/core/event-types.ts)

- `'human-inbox:letter'` payload `{letterId, subject, type, textPreview, senderSessionId, senderTitle, host, kind: 'new'|'reply'}` — emitted by the store on send and on agent reply; consumed by the notification bridge, push, WS.

### Notification envelope

- New kind `'letter'` in NotificationKind; dedupKey `letter:<id>`; title=subject, body=textPreview, sessionId=origin sid; new optional field `letterId`; severity 'info'.
- Letters are EXEMPT from mark-all-read (markRead with no ids skips kind 'letter') and exempt from panel-open auto-read. Read state canonical in the LETTER store; the notification's own read flag mirrors it via the bridge.

### Delivery to origin session (answer / human-reply)

- `sendMessageToSession(originSid, wrapped, {source: 'human-inbox'})` through the existing queue; wrapper text carries the letter subject + the human's choice/text + one instruction: reply with `wn tools call human_inbox_reply '{"letter":"<id>", "text":"..."}'`. Dead session revives via the normal resume path; do NOT touch injectMidTurn/processNext internals.
