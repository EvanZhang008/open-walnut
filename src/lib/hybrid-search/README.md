# hybrid-search

Self-contained hybrid search core: SQLite FTS5 keyword retrieval with an identifier-aware tokenizer, interpretable additive scoring, and an optional semantic rescore lane. Built for personal-tool corpora (tasks, notes, chat transcripts, markdown knowledge bases) in the 10³-10⁵ document range, where queries mix natural language, code identifiers, and CJK text.

This directory is written as a standalone library. It imports nothing outside `node:*`, `better-sqlite3`, `@huggingface/transformers`, and sibling files (a boundary test enforces this). Publishing it later is: copy the directory, add a package.json with `better-sqlite3` as a peer dependency.

## Why it exists

Off-the-shelf engines do not match `operator` against `AcmeEventOperator`, or `自动重试` against a longer CJK run, without server sidecars or dead bindings. The fix is owning tokenization in application code, symmetrically at index and query time. Once you accept that, the engine choice collapses to "cheapest thing that stores your tokens and gives you BM25": SQLite FTS5.

## Design

- **One tokenizer, both sides** (`tokenizer.ts`). Emits two ordered streams: `orig` (whole lowercased tokens, internal `-_.'` preserved, CJK runs whole) and `sub` (camelCase/snake/kebab/digit-boundary splits; ordered CJK bigrams). No stemming. `TOKENIZER_VERSION` is stamped into the index; a mismatch at open wipes it and reports `needsRebuild`.
- **Contentless FTS5** (`db.ts`). `doc` holds raw text (snippets, rescoring, rebuilds); `doc_fts` (`content=''`, `contentless_delete=1`) indexes the token streams with `tokenchars '-_.'` so joined identifiers survive as single FTS tokens. Eight columns: one orig stream per field (title 10, summary 3, note 1, meta 2) and one sub stream per field at ~60% of the orig weight (6 / 1.8 / 0.6 / 1.2, derived from the orig weights so the ratio cannot drift) — a subword hit in a title outranks a whole-word hit in a body, and phrases can never chain across fields. bm25() hardcodes k1/b and normalizes by WHOLE-ROW length, so a one-token title saturates the per-phrase ceiling on a single hit while a long body is penalized 6-28x: a bare-title stub is the bm25 best whatever the column weights are. No weight vector fixes that, and lowering title measurably HURT single-token component queries, so these weights are unchanged and `bodyCoverage` in `query.ts` carries the fix instead. A tokenizer or FTS-layout version bump re-tokenizes from the stored doc rows (seconds); only a doc-schema bump forces a full source re-feed.
- **Write protocol** (`writer.ts`). Single transaction per doc: delete FTS postings, update the row preserving its rowid, reinsert streams, rewrite identifiers, drop stale vectors (with an embedder, a passage whose text did not change keeps its vector at its new seq, `vector-reuse.ts`, so a session that gained a few turns re-embeds only its new passages). A content hash makes unchanged upserts free, and every vector write checks it, so an embed that raced an upsert stores nothing. The reuse splits a changed doc on the host thread, inside the transaction: the new text once, and the old text only when the writer does not still hold the passage keys of its last split (the 256 most recent docs, by id and content hash). The splitter keeps a running token count, so a split is linear in the text: a 63.9k-char note of tiny paragraphs used to take about 250 ms to split on a loaded machine.
- **Two query lanes + additive scoring** (`query.ts`). A strict AND lane for precision (CJK via ordered-bigram phrases), a relaxed OR lane for recall with a document-frequency threshold so corpus-wide terms cannot melt latency. Two more strict lanes score below it (at most 0.8 of the strict share): lane A' ANDs each term's word forms (below), and lane A'' ANDs only the discriminative terms of a query of 4+ terms, so "where is the X task" is not a lane only long transcripts can pass (shorter queries keep every word: in "walnut deploy" the common word is a name). Scores are a weighted sum of normalized BM25 (both lanes) 0.3 / 0.2, term coverage 0.2, **body coverage 0.2**, exact-identifier hits, recency, and (when enabled) cosine similarity, with every component exposed on the hit. The first four sum to 0.9. Term coverage weights each term by rarity, `log(dfCap/df)`, so matching the rare words of a query counts for more than matching its glue; a term no doc holds counts as an average term. Body coverage is the fraction of DISCRIMINATIVE query terms (those that passed the df gate) present in the summary/note streams: presence, not count, so row-length normalization has no grip on it, and skipping high-df terms keeps it from degrading into a document-length bonus. It is off for queries under 3 terms, where a handle lookup should let a bare task win, and a doc whose title is the query's words, or begins with them (the last one perhaps unfinished), is exempt: it is what the query names, and a task's note rarely repeats its own title. The empty `Test <topic>` stub neither is nor begins with `<topic>`.
- **Compound spellings, query side** (`compoundForms` in `query.ts`). One name written as one word or as two (`dockhub` / `Dock Hub`, `setup` / `set up`) shares no token, so each term also matches, as extra OR forms: its two halves as an adjacent phrase (split), its concatenation with a neighbouring query term (join, credited to both terms), and for a joined token like `dock-hub` its parts apart or run together. A form is kept only when every token it needs exists in the index (one `LIMIT 1` probe each, cached per query), with per-term and per-query caps, and queries over 8 terms skip it. The index is untouched: joining adjacent words at index time would roughly double every transcript's sub stream. Versions and dates get the same treatment: `opus-4-8`, `Opus 4.8` and `claude-opus-4-8` meet through their digit groups (`4 8`, `opus 4.8`), never run together (`4.8` is not `48`). Full-width input (a CJK input method in full-width mode) is folded to ASCII first.
- **Word forms, query side** (`wordForms` in `query.ts`). Found by `scripts/search-robustness-eval.mjs`, which rewrites real titles the way people type. A term also matches its inflections (`doctors`/`doctor`, `failed`/`fails`), and a word the index barely holds (df <= 2) is read through its one-edit spelling fixes (ordered by the share of each candidate's own docs that hold the other query words, so a word common everywhere does not win by volume), its inflections, the split phrases of those, and, as the last word, its completions (`card spe` → `spend`). A last word in at most 20 docs is completed too when far commoner words begin with it (`todo sync fai` → `failed`). Forms run in their own strict lane (A'), capped at 0.8 of the strict share, because bm25 scores a form on its own idf and a rarer or busier form outranked the docs that say what was typed. A form both over the df gate and 2x+ commoner than the typed word is another word in practice (`filing`/`file`, `times`/`time`) and is dropped. The vocabulary is read through a TEMP `fts5vocab` view (an IN lookup of 600 terms is ~13ms); a 3-letter native prefix query costs 17-135ms, so completions scan the vocabulary instead.
- **Vectors rescore, never retrieve.** Embeddings (int8 blobs in `doc_vec`) are only compared against the keyword candidate set — full-corpus KNN is out of scope by design. Omit the `embedder` option and you have a pure keyword engine; that degraded mode is a supported deployment shape, not an error.
- **Embedding off the main thread** (`embedder.ts` + `embed-worker.ts`). The ONNX model runs in a child process the host forks (not a worker thread: ending a thread while onnxruntime is inside a run aborts the whole host, so a forced stop, or the host exiting mid-run, used to take the server down). A stop asks the worker to finish its run and exit; only a run that outlives the grace is killed, and a host that exits kills its workers on the way out. An idle worker keeps no host alive; `searchSemantic()` races the query embed against a deadline and falls back to keyword order with a `semantic: 'timeout'` marker. A caller that gives up does not cancel the job: its answer still lands in the query cache for the next caller, and callers asking for the same text while it is computed share one inference. Three consecutive worker crashes disable the semantic lane for the process. Passages come from `chunk.ts`, and EVERY kind is chunked: `passagesForDoc` returns a digest at seq 0 (title + summary + the head of the body, so the recall lane, which reads only seq 0, can still discover a long doc) plus cover passages at seq 1..n that contain every remaining character. Passages are sized by an estimated TOKEN budget (480, under the tokenizer's 512) as well as a 1400-char ceiling, because CJK runs about one token per character and a char-only budget silently truncated Chinese passages inside the embedder. A doc whose whole text fits one passage collapses to a single vector (`coverFrom: 0`). Over `MAX_CHUNKS_PER_DOC` the cap drops text and reports how much as `droppedChars`; `overflow: 'tail'` keeps the newest chunks for chronological bodies, the default `'spread'` keeps both ends for structured ones. `PASSAGE_POLICY_VERSION` is stamped into the index and a mismatch at open drops `doc_vec` (keyword index survives) so the backfill re-embeds under the new layout. A ratchet (`tests/core/search-v2-passage-policy-ratchet.test.ts`) pins a fingerprint of each kind's passages per version, so a change to the splitting rules or to a kind's policy without a bump fails. `backfillVectors()` embeds docs missing vectors in small batches so an indexer loop can pace itself; its walk is bounded by a scan budget per call (`MISSING_VEC_SCAN_LIMIT`) and takes an optional `minUpdatedAt` floor, so an indexer that has already drained once asks about a timestamp range instead of sweeping the table.
- **Batch budget** (`backfillVectors({ budgetMs })`). Once the budget is spent a call stops between two passages (after at least one was tried, so a batch whose docs all fail stops too), keeps what it embedded and hands back the cursor it was given, so a batch of long docs returns to its caller's pacing every few seconds instead of after minutes. A call that fails or is stopped mid-doc keeps the passages it finished too.
- **Quarantine** (`backfillVectors`). A doc is given the zero vector (done, no boost) only when it is the cause: its passage failed twice in a row, and the worker answered a probe passage after each failure. A failure the probe does not explain away (a worker that cannot start, crashes on everything, or cannot load its model), and any stopped run, blames no doc: the call returns `stalled` and the caller tries again later. The zero vector is written under the content hash the doc was listed with, so a doc edited while its passage was judged is not quarantined, and its new text is listed again. A quarantine holds for the rest of the process; the next process retries each zero vector once (the walk hands it out again), so one written by an older version or under a sick worker heals at the next start.
- **Worker lifetime** (`embedder.ts`). Queries and passages run in two worker processes, each with its own model copy (about 2.2 GB of footprint on the default model). The query worker is released after `queryIdleMs` (default 10 minutes) without a query, and the next query reloads it; the passage worker goes when `releasePassageWorker()` is called at the end of a backfill pass, or after its own idle timer.
- **Index-to-index copy** (`replica.ts`). A second host can keep a copy of an index without embedding anything: the source lists every doc with its content hash and vector state (`replica.states`, sliced by id) and exports the docs a copy asks for with their identifier tokens and vectors (`replica.exportDocs`); the copy writes them under the same protocol as the writer, re-tokenizing FTS locally, and stamps each with a caller tag (`replica_tag`). Any local write to a doc drops its stamp. A doc whose text did not change keeps its own vectors when the source sends fewer, so a source re-embedding after a rebuild does not blind the copy. `onDocChange` tells the host which docs a write touched, so it can keep a manifest current without walking the table, and `warmQueryWorker()` loads the query model ahead of the first search.

## Known residue

- **Wrong vectors an old race left behind can outlive changes** (`vector-reuse.ts`, `reusableVectors`). Before vector writes were hash-checked, an embed that raced an upsert could store one version's vectors over the next version's text. `reusableVectors` drops a doc's rows only when their layout shows the race (a seq past the old layout, or a complete doc whose seqs are not exactly 0..n-1). A session at the 40-passage cap keeps the same count across changes, so such rows look right and are carried over until their text slides out of the tail window, or the index is rebuilt. Rows of a partly embedded doc are kept by the resume too. Measured by the r1 gate on a copy of real data: 1,037 sessions at the cap; a planted residue of 37 vectors survived a drain and a restart, and `rebuildAll` cleared it.
- **A change to meta alone still discards an embed in flight** (`writer.ts`, `vecTarget`). The content hash covers meta and identifiers, so an upsert that changes only those during an embed makes every vector write of that embed refuse, and the doc's passages are embedded again (11 of 11 in the gate), although their text did not change. The next change keeps them through the reuse, so the cost is one doc's inference, not wrong vectors.

## Usage

```ts
import { createSearchIndex } from './index.js';

const index = createSearchIndex({
  dbPath: '/data/search.sqlite',
  kinds: { task: { weight: 1.0 }, session: { weight: 0.9, chunkVectors: true } },
  // embedder: { modelId: 'intfloat/multilingual-e5-small', dims: 384,
  //             queryPrefix: 'query: ', passagePrefix: 'passage: ' },
});

index.upsert({
  kind: 'task',
  ref: 't-42',
  title: 'Reconciler duplicate kind across GVRs check',
  note: 'The AcmeEventOperator watch cache keys by kind alone…',
  updatedAt: Date.now(),
  identifiers: ['t-42', 'CR-291543784'],
});

const hits = index.search('kind event operator', { limit: 10 });
// hits[0].components → { bm25Strict, bm25Relaxed, coverage, bodyCoverage,
//                        exactIdent, selfIdent, recency, cosine? }

index.remove('task', 't-42');
index.stats();
index.close();
```

`kind` is an arbitrary caller string, never an enum. Paths, weights, and logging all come in through options; the library reads no environment variables.

## Files

| File | Role |
|---|---|
| `index.ts` | public API (`createSearchIndex`) |
| `tokenizer.ts` | orig/sub token streams, `TOKENIZER_VERSION` |
| `db.ts` | schema, version gates, stats, optimize |
| `writer.ts` | upsert / remove / rebuildAll |
| `vector-reuse.ts` | keeps the vectors of unchanged passages across a content change |
| `missing-vectors.ts` | the backfill's work queue: docs without vectors, bounded per call |
| `query.ts` | lanes, df threshold, gated-pair phrase recall, scoring |
| `embedder.ts` | worker lifecycle, deadlines, crash containment, `cosineInt8` |
| `embed-worker.ts` | child-process query/passage embedding (ONNX, int8) |
| `chunk.ts` | passage extraction (head passage / paragraph chunks) |
| `replica.ts` | index-to-index copy: source states and exports, the copy's import and stamps |
